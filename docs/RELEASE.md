# Clipbox — Release guide

## 1. Сборки

| Профиль (eas.json) | Что это | Команда |
|---|---|---|
| `development` | Dev Client APK, для разработки | `npx eas-cli@latest build -p android --profile development` |
| `preview` | Release-конфигурация (R8, сжатие ресурсов), APK для ручного теста | `npx eas-cli@latest build -p android --profile preview` |
| `production` | AAB для Google Play, автоинкремент versionCode | `npx eas-cli@latest build -p android --profile production` |

- **Подпись:** ключ загрузки (upload key) хранится в EAS (`eas credentials`), Play App Signing — у Google.
  Не коммитить keystore и пароли в репозиторий.
- **Версия:** `expo.version` в `app.json` (semver для людей); `versionCode` ведёт EAS (`appVersionSource: remote`).
- **Release-конфигурация:** `minSdk 29`, R8 (`enableMinifyInReleaseBuilds`) и `shrinkResources` включены
  через `expo-build-properties`; правила R8 модуля — `modules/clipbox-native/android/proguard-rules.pro`
  (оставляют Argon2 Bouncy Castle и вырезают `Log.d/v/i`).
- Локально (нужен Android SDK + NDK): `npx expo prebuild -p android && cd android && ./gradlew :app:assembleRelease`.

## 2. Автоматические проверки (CI, `.github/workflows/ci.yml`)
1. `npm run check`: актуальность бандла Markdown-превью, TypeScript, ESLint (включая правила слоёв), Jest.
2. JVM-тесты криптоядра: `modules/clipbox-native/jvm-tests` (`gradle test`).
3. Android: unit-тесты модуля в Android-сборке + debug APK.
4. `npm audit --omit=dev --audit-level=high`.

## 3. Ручной чек-лист перед релизом (реальное устройство, preview-сборка)

Отмечайте на двух устройствах: Android 10–12 и Android 14+; одно — со сканером отпечатков.

**Основное**
- [ ] Холодный старт до Home < 1.5 с; светлая/тёмная/системная тема; TalkBack читает кнопки.
- [ ] Maestro: `maestro test .maestro` — все потоки зелёные.
- [ ] Заметка: Markdown ⇄ Просмотр, таблица, чек-лист (тап в просмотре меняет исходник), код, картинка.
- [ ] Убить приложение во время набора → текст на месте (≤ 0.6 с потерь).
- [ ] Экспорт заметок ZIP → открыть в Obsidian; импорт папки Obsidian → картинки `![[...]]` видны.
- [ ] Share: ссылка из Chrome, YouTube, TikTok, Reddit; текст из мессенджера; фото из галереи; PDF. Всё в Inbox, без сети тоже.
- [ ] Метаданные подтягиваются при появлении сети; «Повторить» после трёх неудач.
- [ ] Напоминание через 2 минуты: приходит; «Готово»/«Через 1 час» работают; после перезагрузки телефона — приходит.
- [ ] Повтор «каждый день» переживает смену часового пояса (плавающее время).
- [ ] Settings → «Включить точное время» → напоминания минута в минуту.

**Безопасность (SECURITY_DESIGN §12, §14)**
- [ ] Vault/Media после перезапуска процесса — заблокированы.
- [ ] Home/Recents в Private space → превью пустое, скриншот запрещён, запись экрана — чёрная.
- [ ] Vault блокируется сразу при сворачивании; Media — через 60 с; оба — по бездействию.
- [ ] Отмена биометрии; 5 неверных отпечатков (lockout) → вход паролем.
- [ ] Устройство без биометрии → только пароль; добавить новый отпечаток → «биометрия изменилась», вход паролем, повторное включение.
- [ ] Ключ восстановления: забыть пароль → войти ключом → задать новый.
- [ ] Неверный мастер-пароль ×6 → пауза растёт.
- [ ] Скопировать пароль → через 30 с буфер пуст (если там всё ещё наш текст); превью буфера на Android 13+ скрыто.
- [ ] `adb shell run-as app.clipbox` → `files/private/**`, `databases/clipbox.db`: `strings | grep` по известному паролю и по фрагменту текста записи → 0 совпадений.
- [ ] После импорта/просмотра/отправки Media: нет файлов в `/sdcard`, MediaStore (галерея) их не показывает; `cache/share-out` пуст через 10 мин.
- [ ] Отправка из Private Media в Telegram, Discord, WhatsApp (фото, GIF, видео) — файлы приходят.
- [ ] Видео > 1 ГБ: перемотка работает, память стабильна.
- [ ] Бэкап `.cbvault` → удалить приложение → установить → настроить Vault и Media → восстановить. Порченый файл (изменить байт) → отказ.
- [ ] `adb logcat` за весь прогон: нет паролей, имён файлов из Media, текстов записей.
- [ ] Уведомления никогда не содержат данных Vault/Media.

## 4. Google Play — Data safety (черновик ответов)
- **Сбор данных:** нет. Аналитики, рекламы, crash-SDK нет; аккаунта и сервера нет.
- **Передача третьим лицам:** нет.
- **Сеть:** только загрузка метаданных и превью ссылок, которые пользователь сам сохранил,
  и открытие ссылок по нажатию. Без cookies и идентификаторов.
- **Шифрование:** Vault и Private Media — AES-256-GCM на устройстве; передачи по сети нет.
- **Удаление данных:** всё локально; удаление приложения удаляет данные.
- **Разрешения:** уведомления, точные будильники (опционально), биометрия, интернет.
  Push (FCM), бейджи лаунчеров, install referrer — заблокированы в манифесте.

## 5. Известные ограничения v1.0
- Только Android. Синхронизации нет (by design).
- Пока запись Vault открыта на экране, её поля находятся в памяти JS-движка (T10).
- Кнопки «Готово/Отложить» в уведомлении открывают приложение (надёжность важнее; фоновая обработка — позже).
- Отправка из Private Media создаёт временную расшифрованную копию во внутреннем кэше (≤ 10 мин).
- Разблокировка PIN-кодом устройства не поддерживается (только Class 3 биометрия и мастер-пароль).
